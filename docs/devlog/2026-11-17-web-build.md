# Browser build
<!-- index | refs: #97 | area: Web, persistence -->

**Date:** 2026-11-17 · **Issue:** [#97](https://github.com/vectorviolet/highrise/issues/97)

## Context and decision

The owner requested the same browser support as Chokepoint, including the lessons
from its first port. This implementation reuses that build recipe and preserves
Highrise's desktop gameplay. Desktop browsers with a keyboard and mouse are the
target; mobile controls are outside this issue's scope.

The loading screen uses the existing Highrise cover with Chokepoint's readable
progress and click-to-play controls. The browser skips the threaded intro, hides
desktop-only settings and opens a Thanks for playing screen on Exit. Fullscreen
uses the browser API. The music is the same licensed track encoded as OGG.

## Persistence and startup

Highrise's startup must load its board and settings before the async loop. Its
desktop SQLite persistence stays in place; browser progress uses a namespaced
SaveStore in localStorage. No player database is included in the web archive.
[ADR 0004](../decisions/0004-web-build.md) records the alternatives and reasoning.

## Build and release

The pinned pygbag tool stages only runtime files, vendors pure-Python PyYAML and
retries a failed build once. The release pipeline builds desktop and web artifacts
independently. A tag publishes the html5 channel; a manual workflow builds artifacts
without publishing. The owner enables the browser upload on itch.io after the first
release.

## Verification

The branch was merged with main on 2026-11-18 after saving the web work in a WIP
commit. It retains the Windows installer jobs and pygamine `0049da0`, including
`packaged_data_dir` for desktop saves. The browser ADR is 0004; ADR 0003 describes
the packaged save location.

The first browser playtest exposed a startup error in the hidden-settings rows,
a stale fullscreen label and an uncleared Exit background. The row lookup now
uses the engine's supported API, the label follows completed browser fullscreen
changes, and the Thanks panel clears the background every frame. Regression
coverage includes these paths, save restoration in a new game instance, and
saving during an unfinished merge. Browser world updates preserve the desktop
movement rate while rendering at 60 FPS.

All 774 app tests (including 10 browser regression tests), 1,106 engine tests,
the desktop smoke test, Ruff formatting/lint, mypy and codespell pass. Regenerating the desktop
README media produces no changes. A fresh pygbag build produces five files
(14,097,077 bytes), within the HTML5 upload limits.

Final visible Chrome verification of reload/Continue, fullscreen and Exit is
pending: the computer-use service is unavailable, and the owner has been asked
to check the fresh local preview. Automated storage tests do not substitute for
that browser check. Focused-browser performance and audio still need manual
validation before release.
